05 每日一个 AI 赚钱案例：DeepSeek Harness 插件生态（插件作者）只写公开可核实的收入与价格，关键数据不公开就明说

产品卖给谁：DeepSeek Harness 的 154 万日活跃用户（以使用官方 API 的用户为统计范围）

收费方式：官方 Token 激励的具体金额与发放标准未公布；插件市场定价机制未公布，暂无公开的插件售价或分成比例

用户主要从哪里来：DeepSeek App 内 Harness 入口；官方插件市场（筹备中）与作品推荐

公开营收信号：截至 11 月 4 日（官方 API 用户口径）：日活跃用户 154 万，日消耗 Token 约 92 万亿；第三方插件约 3.5 万个，约 60% 的活跃用户制作或安装了至少一款第三方插件；官方筹备面向插件作者的支持计划（Token 激励、技术交流、作品推荐）并建设官方插件市场。插件作者的实际收入数据未公开。

竞争优势：DeepSeek App 自带流量入口，Harness 定位“Agent 时代的操作系统”，插件即应用；官方筹备插件市场与推荐位，早期插件有机会吃到平台红利

可能成本结构：开发成本主要是时间；运行成本是 Token 消耗，个别用户反馈一个小型项目 Token 消耗可达 OpenCode 的 20 倍，插件过多会挤占上下文、推高成本，具体金额因插件而异，未公开统一数据

可复制的经验：选一个高频、具体的场景做小插件，而不是做大而全的平台；借 DeepSeek App 的流量与官方市场推荐，而不是自建流量；把插件当作获客入口，再导向自己的付费服务

不适合个人创业者的经验：官方 Token 激励的具体金额与发放标准未公布，分成模式不明；依赖单一平台政策，插件需随 Harness 版本快速适配（有用户升级后 32 个插件条目丢失、修复约 5 小时）；只做插件等于把收入命脉交给平台规则

06 对我最有价值的一个行动具体、可执行、低成本

花 30 分钟做一次 Agent 安全自查：不要在 ~/Downloads 或桌面启动 Claude Code 或 Codex；检查 ~/.codex/config.toml 与各项目 .claude/settings.json 有无陌生网关或 mcp_servers 节点；把 .claude/settings.local.json 加入 .gitignore；轮换一次曾交给 Agent 的高风险 API Token。
